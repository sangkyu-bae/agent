# 고칠 표현과 대체어

`plain-tone` SKILL.md §2의 다섯 갈래를 표로 펼친 것이다.
표에 없는 표현을 만나면 같은 갈래의 기준으로 판단하고, 작업 끝에 "추가 후보"로 사용자에게 알린다.
이 파일은 사용자가 요청할 때만 고친다.

## A. 내부 조어 · 번역투 명사

이 프로젝트 안에서만 통하는 이름. 독자에게는 **무엇이 무엇을 하는지**로 바꾼다.

| 조어 | 바꿔 쓰기 | 비고 |
|------|-----------|------|
| 응답봉투, 메시지 envelope | 서버가 보내는 메시지의 공통 형식(종류·내용·시각) | 개발자 독자에게도 "envelope"는 처음 한 번 풀어 쓴다 |
| 환류, 피드백 환류 | 평가를 다음 답변에 반영 | |
| 스코프 표류 | 처음 정한 범위를 벗어나는 것 | |
| 비목표로 못 박다 | ~는 하지 않기로 정했다 | B 갈래와 겹침 |
| 승인 게이트, 게이트 | 사람이 승인해야 다음으로 넘어가는 단계 | 비전공자: "결재" |
| 결재함 | 승인 대기 목록 | 화면 이름이 "결재함"이면 그대로 쓰고 괄호로 설명 |
| 근거 판정, 근거 판정 루프 | 답변에 근거 없는 주장이 있는지 검사하고 다시 쓰는 과정 | |
| 재작성 루프 | 검사에서 걸리면 다시 쓰기 | |
| 드릴다운 | 실행 단위로 내려가 보기 | |
| 역설계 | 다시 읽고 공통 요구를 뽑기 | |
| 검증 무대, 첫 무대 | 처음 적용한 부서 | |
| 미들웨어 조합 | 압축·마스킹·재시도 같은 공통 처리를 끼워 넣기 | 개발자 독자에게는 "미들웨어"까지는 허용 |
| 관측, 관측 체계 | 실행 기록 | 개발자 독자에게 "observability"는 허용 |
| 신원 헤더 | 호출마다 누가 실행하는지 담은 서명 토큰 | |
| 동적 컴파일 | 요청 때마다 그래프를 만들어 실행 | |
| 폴백 | 실패하면 다른 모델로 바꿔 시도 | |
| 청킹 프로파일 | 문서를 나누는 규칙 | |
| 3계층 요약 | 카드·섹션·문서 단위로 미리 만든 요약 | |
| 조직 지식 승인 게이트 | 한 사람의 피드백이 부서 전체 답변에 반영되기 전에 승인받는 단계 | |
| 라이프사이클 | 만들고 쓰고 고치고 없애기까지 | |
| 양성 대조군 | 정상 문장을 넣어 오판하는지 본 것 | |

**조어가 아닌 것 (개발자·관리자 독자에게는 그대로 쓴다):**
- 업계 통용어: 할루시네이션, 승인 게이트, 미들웨어, 프롬프트 인젝션, 임베딩, 청킹, 스케줄러, 레지스트리, 라우팅
- 표준 용어·고유명사: RAG, MCP, BM25, RRF, Qdrant, Elasticsearch, LangGraph, LangChain, JWT, Fernet, RAGAS, Kiwi, gpt-4o, WebSocket, Pydantic
- 기능 이름은 `project-story` §3의 모듈 이름("할루시네이션 방지 모듈", "실행자 신원 전달", "MCP 레지스트리")을 쓴다.

비전공자 독자에게는 `doc-writer/references/glossary.md`를 따른다.

| 라벨 조어 | 바꿔 쓰기 |
|-----------|-----------|
| 넣은 장치, 장치 | 기능, 모듈, 해결 방법 |
| 문제 → 넣은 장치 → 바뀐 것 | 문제 / 해결 / 효과 |
| 걱정 | 우려 (표 제목·격식 문맥), 걱정 (경영진·실무자용 쉬운 문서에서는 허용) |

## B. 과장 · 비유 동사

격식체 동사로 바꾼다. 쉬운 말로 바꾼다고 구어체(F)로 가지 않는다.

| 과장 · 비유 동사 | 격식 있는 실제 행위 동사 |
|-----------------|------------------------|
| 진화시켰다, 진화했다 | 다시 설계했다, 변경했다, N번 개선했다 |
| 고도화했다 | 개선했다, 추가했다 (무엇을) |
| 확보했다 | 얻었다, 높였다, 유지했다 |
| 쌓았다 (겹으로) | 단계로 구성했다 |
| 못 박았다 | 정했다, 명시했다 |
| 끌어올렸다, 극대화했다 | 높였다 (수치가 있으면 수치로) |
| 혁신했다 | (삭제하고 한 일을 쓴다) |
| 강화했다 | 추가했다, 차단했다 |
| 실현했다, 달성했다 | 했다, 됐다 |
| 선보였다 | 추가했다, 제공했다 |
| 수립했다 | 정했다, 세웠다 |
| 정립했다 | 정리했다 |
| 보장했다 | 차단했다, ~되도록 했다 |
| 봉인했다 | 규칙으로 정했다 |
| 가로채다 | 먼저 받아서, 중간에서 받아 |
| 살아 있다 (세 세대가) | 함께 사용된다 |

**과장이 아니므로 그대로 쓰는 격식체 동사:** 구현했다, 적용했다, 도입했다, 설계했다, 구성했다, 제공했다, 등록했다, 연결했다, 저장했다, 기록했다.

## C. 모델 습관 문장

### C-1. 대구 · 경구
운율을 맞추거나 격언처럼 들리게 만든 문장. 사실 문장으로 푼다.

| 원래 | 고친 것 |
|------|---------|
| 판단은 사람의 시간에, 집행은 시스템의 시간에 하도록 분리했습니다. | 사람이 승인하면 시스템이 지정한 시각에 보냅니다. |
| 문서가 코드보다 앞서 가지 않게 했습니다. | 문서와 코드가 다르면 문서를 고치지 않고 보고합니다. |
| 코드보다 앞서 "누가, 왜"를 정했습니다. | 코드를 쓰기 전에 누가 쓸지부터 정했습니다. |

### C-2. 반전 구조
"~가 아니라 ~다"는 한 문서에 한 번이면 충분하다. 두 번째부터는 뒤쪽만 남긴다.

| 원래 | 고친 것 |
|------|---------|
| 설계 문서가 장식이 아니라 게이트가 되도록 한 것입니다. | 설계와 코드가 90% 이상 맞지 않으면 완료로 치지 않았습니다. |
| 문제는 모델 성능이 아니라 "어디까지 믿게 할 것인가"였습니다. | 가장 어려웠던 것은 AI 답변을 어디까지 믿게 할지 정하는 일이었습니다. |
| 규정 문서는 문단이 아니라 조·항이 의미 단위이므로 | 규정 문서는 조·항 단위로 뜻이 나뉘므로 |

### C-3. 문단 끝 교훈 · 요약
마지막 문장이 앞 내용을 되풀이하거나 교훈을 붙이면 지운다.

- "~한 것입니다." / "이것이 ~의 핵심이었습니다." / "결국 ~로 이어졌습니다." / "이 경험은 ~를 가르쳐 주었습니다."
- "그 결정이 이후 모든 ~에 같은 장치를 재사용하게 해 주었습니다." → 사실이면 "이후 외부 발송 초안에는 모두 같은 검사를 붙였습니다."로 사실만 남긴다.

### C-4. 셋 묶기
항목이 꼭 셋이어야 할 이유가 없으면 실제 개수대로 쓴다. 둘이면 둘, 다섯이면 다섯.

### C-5. 명사 나열 · 군더더기 동사

| 원래 | 고친 것 |
|------|---------|
| 설계·구현·검증을 수행했습니다 | 설계하고 구현하고 검증했습니다 |
| 개발을 진행했습니다 | 개발했습니다 |
| 적용을 수행했습니다 | 적용했습니다 |
| 활용하여 | ~로, ~를 사용해 |
| 수행 (다른 동사 뒤에 붙은 경우) | (삭제) |
| 제공합니다 | ~할 수 있습니다 → 가능하면 동작 문장으로 |
| ~를 통해 | ~로 |
| ~를 기반으로 | ~로, ~에 따라 |
| ~에 대한 | ~의, (삭제) |
| ~하는 것을 가능하게 했습니다 | ~하게 했습니다 |
| ~할 수 있도록 지원합니다 | ~할 수 있습니다 |
| ~함으로써 | ~해서 |
| ~에 있어서 | ~에서, (삭제) |

### C-6. 겉치레
- 모든 항목 앞 이모지 → 뺀다.
- 문장 안 굵은 글씨 → 항목 이름에만.
- "본 프로젝트는", "본 문서는" → "이 프로젝트는", "이 글은".
- "~라고 할 수 있습니다", "~것이다" 체 → 단정문.
- 따옴표로 감싼 개념어("신뢰의 문제") 남발 → 한 문서에 두 개 이하.

## D. 모호어

수치·동작으로 바꾸거나 지운다. 그대로 두는 경우는 없다.

| 모호어 | 바꾸는 방향 |
|--------|------------|
| 다양한 | 실제 항목 나열 ("메일·문의 조회·일정 등록") |
| 효율적으로, 효과적으로 | 무엇이 얼마나 줄었는지, 없으면 삭제 |
| 원활한, 원활하게 | 삭제 |
| 체계적으로 | 어떤 순서·규칙으로 했는지 |
| 안정적으로 | 무엇이 죽지 않는지 ("서버 하나가 꺼져도 나머지 도구는 동작") |
| 유연하게 | 무엇을 바꿀 수 있는지 |
| 적절히, 적절한 | 기준을 쓰거나 삭제 |
| 상당히, 크게, 대폭 | 수치, 없으면 삭제 |
| 일정 수준, 어느 정도 | 수치, 없으면 삭제 |
| 전반적으로 | 삭제 |
| 강력한, 지능형, 차세대, 최적의, 혁신적인 | 삭제하고 한 일을 쓴다 |
| 손쉽게, 간편하게 | 몇 단계인지 ("등록 한 번으로") |
| 다각도로, 종합적으로 | 실제 관점 나열 |
| 최신 | 버전·시점 |
| 핵심 가치, 핵심 역량 | 삭제하고 내용만 |
| 시너지 | 삭제 |
| 고품질, 높은 품질 | 어떤 기준에서 (RAGAS 점수 등) |

## E. 확인 안 된 사실 · 진행형

| 표현 | 처리 |
|------|------|
| 운영 중입니다, 사용 중입니다 | 부서·기간 근거가 있을 때만. 없으면 빼고 "확인 필요" |
| N% 절감, N배 향상 | 측정 기록이 있을 때만 |
| ~로 나아가고 있습니다, ~로 옮겨 가고 있습니다 | 삭제. 지금 되는 것만 쓴다 |
| ~를 지향합니다, ~를 목표로 합니다 | 소개 글에서는 삭제. 포부 문단에서만 허용 |
| 점점 ~할 예정입니다 | 삭제 |
| 성장하는, 진화하는 | 삭제 |
| 검증된, 입증된 | 무엇으로 검증했는지 쓰거나 삭제 |

## F. 구어체 · 가벼운 표현

공식 문서(포트폴리오, 소개서, 관리자 안내, README)에서는 입말을 쓰지 않는다.

| 구어 | 격식체 |
|------|--------|
| 붙는다, 붙인다 (도구·시스템이) | 연결된다, 추가된다, 연동된다 |
| 끼운다, 끼워 넣는다 | 구성한다, 추가한다 |
| 돌린다, 돌아간다 | 실행한다, 동작한다 |
| 죽는다, 꺼진다 (서버가) | 장애가 발생한다, 중단된다 |
| 찍는다 (로그·PDF를) | 기록한다, 생성한다 |
| 걸어 둔다 (스케줄을) | 등록한다, 설정한다 |
| 잡는다 (문제·청크를) | 검출한다, 검색된다 |
| 뚫린다 | 우회된다 |
| 걷어낸다 | 제거한다 |
| 올린다 (결재함에) | 등록한다, 제출한다 |
| 뺀다 | 제외한다 |
| 고친다 | 수정한다 |
| 넘긴다 | 전달한다 |
| 쓴다 (도구를) | 사용한다 |
| 본다 (결과를) | 확인한다 |
| 쌓여 있다 (초안이) | 등록되어 있다 |
| 열린다 (메일함이) | 접근된다, 조회된다 |
| 막는다 | 차단한다 |
| 짜다 (코드를) | 작성한다 |
| 치지 않는다 (완료로) | 인정하지 않는다 |
| 같이 쓰인다 | 함께 사용된다 |
| ~하자, ~잖아, ~거든, ~해 줘 | (문서에서 쓰지 않음) |

경영진·실무자용 안내처럼 일부러 쉽게 쓰는 문서에서도 종결은 "~합니다/~됩니다"로 유지하고, 동사는 위 격식체를 쓴다.

## 갈래 판별이 애매할 때

- 그 단어를 빼도 문장 뜻이 같다 → 모호어(D). 뺀다.
- 그 단어를 동료가 못 알아듣는다 → 조어(A). 풀어 쓴다. 단, 업계 통용어는 조어가 아니다.
- 그 단어를 빼면 한 일이 작아 보인다 → 과장(B). 작아 보이는 쪽이 맞다.
- 소리 내어 읽으면 광고 문구나 격언 같다 → 모델 습관(C). 사실 문장으로 푼다.
- 회의 자리에서 말로는 하지만 보고서에는 안 쓸 단어다 → 구어(F). 격식체로 바꾼다.
